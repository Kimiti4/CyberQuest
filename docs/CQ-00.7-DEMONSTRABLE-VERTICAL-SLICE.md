- **Audience:** adults 18+, synthetic demo only.

## Product objective

Deliver one complete learning interaction: Phishing Detective — Suspicious Invoice, set in fictional Nexus Corporation. The learner inspects a simulated email, selects warning indicators, chooses a response, submits to the API and receives deterministic feedback.

## Scope and boundaries

- Fictional Nexus Corporation, reserved `.example` domains and inert displayed link text.
- No live identity provider, registration, real learner personal data, account persistence or cloud-provider decision.
- The demo assessment is stateless. Results are not saved.
- The API determines scores and explanations. Clients submit only selected indicator IDs and a response ID.
- No XP, achievements, mastery or competency award is issued by this demo.
- No arbitrary HTML, scripts, executable mission content, attachments or external navigation.
- No actual phishing, device scanning, malware detection, device protection or cyber-range execution.
- The demo is for local/development demonstration. Do not expose it as a public unauthenticated assessment service without a separately reviewed abuse/rate-control and deployment design.

## Learner flow and acceptance criteria

1. Open the demo and see the simulation notice.
2. Read the fictional incident briefing and email.
3. Select any combination of the five warning indicators.
4. Select one response from the fixed options.
5. Submit to the backend.
6. See server-returned score, identified/missed/incorrect indicators, explanations and safe-response feedback.
7. See explicit messaging that progress was not saved and no XP or competency was awarded.

Acceptance:
- [ ] API serves only schema-validated, versioned mission content.
- [ ] API rejects unknown/duplicate indicator IDs and unexpected submission fields.
- [ ] API scoring is deterministic and independent of client-supplied score/XP/mastery fields.
- [ ] Perfect and imperfect submissions have tested results.
- [ ] Android client consumes the API; no client-side authoritative scoring.
- [ ] Web client consumes the API; no client-side authoritative scoring.
- [ ] Both clients clearly label the exercise as a simulation.
- [ ] No identity, persistence, XP or mastery is introduced.
- [ ] Clean CI builds/tests all affected platforms.
- [ ] API contract, docs and traceability are reconciled.

## Verification plan

- Backend unit/API tests for valid, invalid, duplicate, unknown and oversized submissions.
- Contract tests for mission payload and result fields.
- Android JVM tests for response parsing and state transitions; build and lint.
- Web typecheck, component/interaction tests, production build and API lint.
- Manual end-to-end demo against a local API; record environment and exact commands.
- Physical Android device validation remains pending until founder installs the APK.
- Public beta, identity, privacy operations/legal review, retention policy, hosting region and production controls remain deferred gates.

## Explicit non-claims

A passing deterministic demo test does not prove identity security, authorization, data protection compliance, production readiness, real phishing detection, real device protection or competency mastery.
