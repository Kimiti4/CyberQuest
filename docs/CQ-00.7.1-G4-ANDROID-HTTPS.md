### 5.2 Defect found during provisioning — cleartext fallback at the tunnel edge

- **Defect:** the first external verification run failed `http_fallback_rejected`: the Cloudflare edge served the demo over plain HTTP and returned mission content to a cleartext request. The Android client was unaffected (it is HTTPS-only), but the temporary endpoint violated the plan's "no cleartext fallback" requirement.
- **Root cause:** the tunnel terminates TLS at the edge and forwards plain HTTP to the loopback origin, so the origin could not distinguish client schemes from the request alone.
- **Fix:** the gateway now fails closed on the scheme the edge reports (`X-Forwarded-Proto`, and `CF-Visitor` as a second signal) and rejects cleartext with `403 https_required`; enabled with `--require-forwarded-https`. Commit `cdeb184e1f65aa9affae69c735392228b89a6e93`.
- **Spoof resistance:** a cleartext request with a client-supplied `X-Forwarded-Proto: https` header is still rejected — the edge overwrites the header, so the client value cannot bypass the check.
- **Regression tests:** five new gateway tests cover enforcement, missing headers, cleartext, `CF-Visitor` mismatch and non-forwarding of edge headers to the origin.
