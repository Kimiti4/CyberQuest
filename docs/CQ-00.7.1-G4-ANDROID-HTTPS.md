### 3.4 G7.1 gateway hardening corrections

The founder's CQ-00.7.1-G7 review found that several safety properties still depended on operator-supplied arguments or on string-prefix checks. They are now mandatory invariants:

| Review item | Correction |
|---|---|
| Loopback-only gateway binding | The `--host` argument was removed; the gateway always binds `127.0.0.1` (`GATEWAY_BIND_HOST`). Attempting to pass `--host` is an argument error. |
| Mandatory HTTPS-edge enforcement | `--require-forwarded-https` and the `require_forwarded_https` option were removed. Every request must carry `X-Forwarded-Proto: https` (all occurrences); missing, cleartext or mixed values are rejected with `403 https_required`. |
| Structural upstream validation | `validate_upstream_base_url` parses the URL and accepts only plain HTTP to `127.0.0.1` or `::1`, with no userinfo, path, query, fragment or out-of-range port. DNS names such as `localhost` are rejected. Validation runs in `GatewayConfig.__post_init__`, so no caller can construct a gateway with an invalid origin. |
| Rate-limit documentation | Documentation now states the actual semantics: limits are keyed by TCP peer address; behind one tunnel connector all requests share the loopback peer, so each limit applies to the tunnel as a whole, not per remote end user. |
| Regression coverage | Gateway suite 21 → 40 tests, including the invariant tests listed in 3.1. The full local suite is 85 tests (81 passed, 4 PostgreSQL tests skipped without `DATABASE_URL`); Ruff clean. |

### 5.3 Defect found during provisioning — cleartext fallback at the tunnel edge

- **Defect:** the first external verification run failed `http_fallback_rejected`: the Cloudflare edge served the demo over plain HTTP and returned mission content to a cleartext request. The Android client was unaffected (it is HTTPS-only), but the temporary endpoint violated the plan's "no cleartext fallback" requirement.
- **Root cause:** the tunnel terminates TLS at the edge and forwards plain HTTP to the loopback origin, so the origin could not distinguish client schemes from the request alone.
- **Fix:** the gateway fails closed on the scheme the edge reports (`X-Forwarded-Proto`, and `CF-Visitor` as a second signal) and rejects cleartext with `403 https_required`. Originally added as the opt-in `--require-forwarded-https` flag in `cdeb184e1f65aa9affae69c735392228b89a6e93`; G7.1 removed the flag and made enforcement unconditional.
- **Spoof resistance:** a cleartext request with a client-supplied `X-Forwarded-Proto: https` header is still rejected — the edge overwrites the header, so the client value cannot bypass the check.
- **Regression tests:** five new gateway tests cover enforcement, missing headers, cleartext, `CF-Visitor` mismatch and non-forwarding of edge headers to the origin.
