# CQ-00.5 — Android and Web Reproducible Build Foundations

**Scope:** buildable client scaffolds, pinned toolchains, independent CI jobs and OpenAPI contract validation. No authentication, learner features, production deployment or cross-client runtime integration is included.

## Ratified architecture constraints

- ADR-0004: one CYBERQUEST platform; Android and web are clients of the same FastAPI modular monolith.
- ADR-0005: offline events are untrusted submissions; the server alone validates and awards authoritative outcomes.
- CQ-00.5 introduces no API endpoint or client-side authority.

## Android scaffold

- Kotlin 2.2.21; Android Gradle Plugin 8.11.1; Gradle 8.13; JDK 17.
- Compose compiler plugin follows Kotlin 2.2.21.
- Compile/target SDK 36; minimum SDK 26.
- Gradle wrapper scripts are committed; the official wrapper JAR is stored as base64 text, checksum-verified and materialized by POSIX and PowerShell scripts; distribution URL and SHA-256 are pinned. Invoke with `sh ./gradlew` on POSIX until executable file mode is set.
- CI acceptance: Linux clean wrapper invocation, unit tests, debug APK assembly and Android lint; Windows wrapper materialization, checksum and Gradle startup smoke test.
- Emulator/instrumentation smoke tests are a separate acceptance item; this checkpoint does not claim device execution unless CI evidence shows it.

## Web scaffold

- Next.js 16.4.0; React 19.3.0; TypeScript 5.9.3; Node 24.22.3; npm 11.19.1.
- `web/package-lock.json` is committed and CI now performs `npm ci` only; the one-time bootstrap and isolated lock-commit job have been removed from the final workflow. The committed lock has 308 package entries, 307 resolved packages with integrity hashes and SHA-256 `b1ee9065901b18543385e071878bcf5259a4dd0e10cb75cea8c0c2432805102a`.
- CI acceptance: immutable install from committed lock, typecheck, Node test runner, OpenAPI lint and production build.

## API contract validation

The web job checks the checked-in OpenAPI 3.1 document using Redocly and tests selected invariants:
- learner operations declare bearer authentication;
- mission event schema does not accept client XP/mastery fields;
- expected health and learning paths exist.

This is contract linting and selected structural regression coverage, not runtime API/client integration. Authenticated learner routes remain design-only.

## CI and permissions

- Independent Linux Android, Windows wrapper, web and Python/PostgreSQL foundation jobs.
- Actions are referenced by immutable commit SHA.
- Workflow permissions are read-only for repository contents.
- No secrets, signing keys, production credentials or learner data are required.
- Hosted runner images and remote dependency registries remain external inputs; this is pinned-toolchain reproducibility, not a hermetic build.
