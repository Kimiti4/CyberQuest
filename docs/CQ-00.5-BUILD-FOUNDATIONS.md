# CQ-00.5 — Android and Web Reproducible Build Foundations

**Scope:** buildable client scaffolds, pinned toolchains, independent CI jobs and OpenAPI contract validation. No authentication, learner features, production deployment or cross-client runtime integration is included.

## Ratified architecture constraints

- ADR-0004: one CYBERQUEST platform; Android and web are clients of the same FastAPI modular monolith.
- ADR-0005: offline events are untrusted submissions; the server alone validates and awards authoritative outcomes.
- CQ-00.5 introduces no API endpoint or client-side authority.

## Android scaffold

- Kotlin 2.2.21; Android Gradle Plugin 8.11.1; Gradle 8.13; JDK 17.
- Compose compiler plugin follows Kotlin 2.2.21.
- Compile/target SDK 36; minimum SDK 26.
- Gradle wrapper scripts are committed; the official wrapper JAR is stored as base64 text, checksum-verified and materialized by the wrapper script; distribution URL and SHA-256 are pinned. Invoke with `sh ./gradlew` on POSIX until executable file mode is set.
- CI acceptance: clean wrapper invocation, unit tests, debug APK assembly and Android lint.
- Emulator/instrumentation smoke tests are a separate acceptance item; this checkpoint does not claim device execution unless CI evidence shows it.

## Web scaffold

- Next.js 16.4.0; React 19.3.0; TypeScript 5.9.3; Node 24.22.3; npm 10.9.2.
- The initial CI execution bootstraps the npm lockfile only if absent, uploads it as an artifact and commits it through a separate least-privilege job. A dependent clean-checkout job reruns `npm ci`, typecheck, tests, OpenAPI lint and production build from the committed lock. Reproducibility is PASS only when this replay job passes.
- CI acceptance: immutable install from committed lock, typecheck, Node test runner, OpenAPI lint and production build.

## API contract validation

The web job checks the checked-in OpenAPI 3.1 document using Redocly and tests selected invariants:
- learner operations declare bearer authentication;
- mission event schema does not accept client XP/mastery fields;
- expected health and learning paths exist.

This is contract linting and selected structural regression coverage, not runtime API/client integration. Authenticated learner routes remain design-only.

## CI and permissions

- Independent Android and web jobs.
- Actions are referenced by immutable commit SHA.
- Workflow permissions are read-only for repository contents.
- No secrets, signing keys, production credentials or learner data are required.
- Hosted runner images and remote dependency registries remain external inputs; this is pinned-toolchain reproducibility, not a hermetic build.

## Acceptance evidence register

| Requirement | Evidence required | Initial status |
|---|---|---|
| Android project compiles | CI clean Gradle build and debug APK assembly | NOT RUN |
| Android unit tests | CI JUnit result | NOT RUN |
| Android lint | CI lint task result | NOT RUN |
| Gradle wrapper integrity | Committed JAR checksum test and distribution SHA-256 | IMPLEMENTED; TEST NOT RUN |
| Web dependency lock | Committed npm lock; `npm ci` | BOOTSTRAP PENDING |
| Web typecheck/tests | CI logs | NOT RUN |
| OpenAPI lint | Redocly CI result | NOT RUN |
| Web production build | CI build result | NOT RUN |
| API/client integration | Live backend contract tests | NOT IN SCOPE |
| Windows wrapper | Windows runner materializes and verifies wrapper JAR and starts pinned Gradle | NOT RUN |
| Emulator/instrumentation | Emulator-backed smoke test | NOT RUN |

A green documentation test is not evidence of a successful Android or Next.js build. A successful scaffold build does not establish application, authentication, security or production readiness.
