# CQ-00.7.1-G4 — Temporary HTTPS Endpoint Provisioning Runbook

- **Checkpoint:** CQ-00.7.1-G4
- **Status:** IMPLEMENTATION READY, PROVISIONING NOT STARTED.
- **Purpose:** controlled, short-lived procedure to expose the synthetic Phishing Detective demo API over a temporary HTTPS tunnel so the Android debug client can be exercised on a physical device.
- **Not production infrastructure.** This procedure selects no permanent cloud provider, hosting platform, database provider or region.

## Preconditions

- [ ] Founder has provisioned a temporary tunnel service and supplied its hostname/command.
- [ ] A physical Android device is connected via ADB (`adb devices`).
- [ ] Baseline commit recorded (see "Freeze the source baseline").
- [ ] A build-time API URL for the debug APK is agreed (temporary hostname, HTTPS).

Tooling prerequisites for the build machine (Windows, as used for the recorded G4 run):

- JDK 17 (Temurin) with `JAVA_HOME` set — required by Gradle and by `sdkmanager`.
- Android SDK with `platform-tools`, `platforms;android-36` and `build-tools` installed, **and SDK licences accepted** (`sdkmanager --licenses`). Without accepted licences the Gradle build fails with "Failed to install the following Android SDK packages as some licences have not been accepted".
- `adb` on `PATH` or pointed at by `CYBERQUEST_ADB`.
- The device must have USB debugging authorised (`adb devices` shows `device`, not `unauthorized`; re-prompt with `adb kill-server` + `adb start-server`).
- The device must allow installs over USB: the first `adb install` may raise an on-device confirmation dialog that has to be accepted, otherwise the install is rejected.

## 2. Start the local demo service (loopback only)

```
$env:PYTHONPATH = "src"
python -m uvicorn cyberquest.main:app --host 127.0.0.1 --port 8000
```

Confirm the two permitted routes locally and confirm no database is attached (the demo is stateless; `persistence` must be `not_saved`):

```
curl http://127.0.0.1:8000/v1/demo/missions/phishing-detective
curl -X POST http://127.0.0.1:8000/v1/demo/missions/phishing-detective/assessment \
  -H "Content-Type: application/json" \
  -d '{"selected_indicator_ids":["sender_domain"],"response_id":"verify_and_report"}'
```

No production database, learner account or persistent reward system is connected. `DATABASE_URL` must remain unset.

## 3. Start the exposure gateway (loopback only)

The gateway is the only component the tunnel forwards to. It enforces the route/method allowlist, body limit, rate limits, timeouts and minimal logging.

```
$env:PYTHONPATH = "src"
python -m cyberquest.g4_gateway --upstream http://127.0.0.1:8000 --port 8099 --health-port 8098
```

Defaults: 16 KiB body limit, 60 GET/minute and 10 POST/minute keyed by the TCP peer address. The gateway always binds `127.0.0.1` (the bind address is not configurable) and refuses to start unless the upstream is plain HTTP to a loopback IP literal (`127.0.0.1` or `::1`) with no userinfo, path, query or fragment.

HTTPS-edge enforcement is unconditional; there is no flag to disable it. The tunnel terminates TLS at its edge and forwards plain HTTP to the loopback origin, so the origin cannot otherwise tell an HTTPS client from a cleartext one. The gateway fails closed on the scheme the edge reports (`X-Forwarded-Proto`, cross-checked against `CF-Visitor`) and answers cleartext or missing headers with `403 {"detail": {"code": "https_required"}}`. The edge overwrites these headers, so a remote client cannot spoof them — verified against the live endpoint.

Because the limits are keyed by TCP peer, every request arriving through the single tunnel connector shares the loopback peer key: each limit applies to the tunnel as a whole, not per remote end user. This is acceptable for the single-founder G4 window and is recorded as a limitation, not a per-user control.

Local negative checks before exposing anything (the edge header is required even on loopback, so it must be supplied here):

```
curl -i -H "X-Forwarded-Proto: https" http://127.0.0.1:8099/health/live                 # expect 404
curl -i -H "X-Forwarded-Proto: https" -X DELETE http://127.0.0.1:8099/v1/demo/missions/phishing-detective   # expect 405
curl -i -H "X-Forwarded-Proto: https" http://127.0.0.1:8099/docs                         # expect 404
curl -i -H "X-Forwarded-Proto: https" -X POST http://127.0.0.1:8099/v1/demo/missions/phishing-detective/assessment \
  -H "Content-Type: application/json" -d @big-body.json   # expect 413
curl -i http://127.0.0.1:8099/v1/demo/missions/phishing-detective   # expect 403 https_required
```

## 4. Start the temporary tunnel

Provider-specific. The only requirements:

- The tunnel forwards **only** to the gateway's loopback port. It must not forward the FastAPI port, the dev web server port, or any other development port.
- The public hostname is temporary and recorded, together with an expiry time.
- No long-lived access credential is embedded in the Android APK. If the provider requires an access token, it stays in the tunnel connector process and the endpoint's protection is recorded as part of the evidence.

Recorded G4 run used a Cloudflare quick tunnel (no account, revocable by stopping the connector):

```
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8099
```

The connector prints the temporary hostname (`https://<random>.trycloudflare.com`) in its log; record it together with the start timestamp.

Record: provider, hostname, start timestamp, planned expiry (max 24 hours).

## 5. Verify externally (from outside the development machine)

```
$env:CYBERQUEST_G4_BASE_URL = "https://<temporary-hostname>"
$env:CYBERQUEST_G4_REPORT = "<path>/g4-endpoint-report.json"
python scripts/verify_g4_endpoint.py
```

The script performs the approved acceptance checks: HTTPS-only, TLS chain and hostname validation, invalid hostname rejection, cleartext fallback rejection, mission retrieval, valid and incorrect assessments, unknown route rejection, unsupported method rejection, oversized body rejection, and rate-limit throttling. It exits non-zero if any check fails, and writes a machine-readable report.

## 6. Build the Android debug APK with the temporary URL

```
cd android
.\gradlew.bat --no-daemon --no-build-cache -PCYBERQUEST_DEMO_API_BASE_URL=https://<temporary-hostname> assembleDebug
```

The build fails if a non-HTTPS URL is supplied. Record the APK SHA-256:

```
Get-FileHash .\app\build\outputs\apk\debug\app-debug.apk -Algorithm SHA256
```

Confirm the APK contains no production credential and no permanent endpoint (only the temporary hostname, if any).

## 7. Run the G4 device tests

Install once (the device shows a one-time "Install via USB" confirmation that must be
accepted on-screen; a rejected install is a device-side policy prompt, not an app defect):

```
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

Then run the acceptance flow (mission load, correct-indicator selection, safe-response
choice, submission, server result and guidance rendering), recording screenshots and a
JSON report:

```
$env:CYBERQUEST_ADB = "C:\path\to\adb.exe"
python scripts/verify_g4_device.py `
    --apk .\app\build\outputs\apk\debug\app-debug.apk `
    --skip-install `
    --screenshots C:\path\to\g4-shots `
    --report C:\path\to\g4-device-report.json
```

The script selects exactly the five warning indicators by label (sender domain, reply-to
mismatch, urgency pressure, unexpected invoice, unverified link) — the three "not
suspicious" decoys must stay unchecked for a perfect score — and taps the independent
verification response before submitting.

Record: device model, Android version, APK SHA-256, mission retrieval result, assessment
submission and server result (`10 / 10` with guidance for every indicator), guidance
rendering, failure handling (server stopped, network loss, invalid response) and
reconnection.

G4 requires evidence of actual Android-to-API communication. A successful `curl`, a
browser test, or a successful APK build alone does not pass G4.

- [ ] Public hostname disabled or revoked.
- [ ] Exposure gateway stopped.
- [ ] FastAPI demo process stopped.

- [ ] External reachability test confirms the endpoint is unavailable.
- [ ] Teardown timestamp recorded.

## Operational limits

| Item | Limit |
|---|---|
| Initial provisioning | One test session |
| Maximum active exposure | 24 hours |
| Assessment POST rate | 10 requests/minute per tunnel (shared TCP-peer bucket) |
| Mission GET rate | 60 requests/minute per tunnel (shared TCP-peer bucket) |
| Request body limit | 16 KiB |
| Log retention | Delete after acceptance review, absent an incident |
| Public data | Synthetic only |
| Extension | Explicit founder approval only |

The 24-hour limit is an operational ceiling, not an automatic guarantee from the tunnel service: a person must verify the tunnel is stopped.
