## 4. Security findings and corrective actions

| Finding | Root cause | Correction | Regression evidence |
|---|---|---|---|
| Cleartext requests were served by the tunnel edge during first G4 provisioning | TLS terminates at the tunnel edge; the loopback origin could not distinguish client schemes | Gateway fails closed on the edge-reported scheme (`X-Forwarded-Proto`, cross-checked with `CF-Visitor`); cleartext returns `403 https_required`; client-supplied headers cannot bypass it (edge overwrites them). Originally added as an opt-in flag in `cdeb184`; made unconditional in `936e0ad` (G7.1-04) | Commit `cdeb184`; five new gateway tests; live spoof attempt rejected. Gateway suite now 40 tests |
| **Gateway bind address was operator-configurable** (`--host`) | A security property depended on an operator-supplied CLI default | `--host` removed; the gateway always binds `127.0.0.1`; the bind address is not configurable | `test_gateway_bind_host_is_not_configurable`, `test_gateway_always_binds_loopback`; `936e0ad` |
| **HTTPS-edge enforcement was opt-in** (`--require-forwarded-https`) | The flag defaulted off, so tunnel exposure depended on operator discipline | Flag and `require_forwarded_https` option removed; every request must carry `X-Forwarded-Proto: https` (all occurrences); missing, cleartext or mixed values are rejected | `test_https_edge_assertion_is_mandatory`, `test_https_edge_assertion_has_no_opt_out`, `test_forwarded_http_is_rejected_when_the_edge_reports_cleartext`, `test_cf_visitor_scheme_is_checked_as_well`; `936e0ad` |
| **Upstream origin validated by string prefix** | `startswith("http://127.0.0.1")` / `startswith("http://localhost")` did not parse the URL and accepted DNS names and suffix tricks | `validate_upstream_base_url` parses the URL and accepts only plain HTTP to `127.0.0.1` or `::1`, with no userinfo, path, query, fragment or out-of-range port; enforced in `GatewayConfig.__post_init__` | 14 invalid-URL cases plus loopback acceptance tests; `936e0ad` |
| **Rate-limit documentation claimed per-source semantics** | The limiter keys by TCP peer; one tunnel connector collapses every request to one loopback peer | Documentation now describes the actual shared-tunnel bucket; implementation unchanged | G4 doc §3.1, runbook §3 and Operational limits, register §7 |
| **Register named a stale PR #8 head; PR #6 description was stale** | A hard-coded head in a mutable document cannot track later commits; PR #6's description was not maintained after stacked work | §1 uses evidence-head + live-ref accounting; PR #6 was rewritten to its actual head, CI and current gate status | This register §1–§2; PR #6 description; founder finding 2026-11-16 |
| Next.js 16.4.0 affected by critical/high advisories | Pinned vulnerable release | Upgraded to advisory-bounded `next@16.4.1` (within the approved 16.4 line) | `docs/CQ-00.7.1-S1-NEXTJS-SECURITY.md`; exact-head CI green on `e046199` and `41cefcd` |
| Lockfile regeneration dropped `ajv@8.20.0`, breaking clean `npm ci` in CI | `--legacy-peer-deps` regeneration; warm `node_modules` masked it locally | Lock regenerated under default peer resolution; clean `npm ci` added to the verification discipline | Failed run `43657976777` retained; corrective run green `43658946000` / `43658945955` |
| Oversized request body echoed in `422` response (G2) | Validation response echoed submitted input; no body size control | ASGI body-limit middleware (64 KiB) rejecting with `413 request_too_large` before parsing; no payload echo | `docs/CQ-00.7.1-G2-NEGATIVE-EVIDENCE.md`; tests added in `a26f1ce` |
| Feedback returned only the indicator label, not teaching guidance (G3) | `explanation` reused the label | Added `guidance` per indicator in content, API, OpenAPI and both clients | `docs/CQ-00.7.1-G3-EDUCATIONAL-REVIEW.md`; tests added in `e166a21` |
